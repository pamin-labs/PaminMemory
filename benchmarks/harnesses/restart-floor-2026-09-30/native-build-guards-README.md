# Prospective fresh targets and declared native loader inputs

These inert guarded wrappers apply only to a new build and trial. They do not change the archived `build.py.in` or `run.py.in`, historical binary identities, measurements, or unknown historical loader configuration.

`build-guarded.py.in` requires a new output directory outside all source checkouts. It creates a private mode-0700 `targets/<arm>` directory, empty before each arm, and sets that arm's `CARGO_TARGET_DIR` explicitly. No shared-target clean or cached Cargo artifact is used. Every emitted `compiler-artifact`, including third-party libraries, proc macros and build-script executables, must have `fresh:false` and all artifact filenames/executables must resolve inside that target. The full compiler JSON and build-script records are retained. Before output creation and each arm it requires at least 12 GiB free disk and 4 GiB available memory, limited by cgroup headroom where reported. These are conservative policy floors, not measured peak requirements; three independent release targets may need more space. The operator must stop competing builds/trials separately.

The prebuilt zvec library remains an explicitly declared external input: `ZVEC_LIB_DIR=/workspace/.cargo/lib/pamin` and `ZVEC_AUTO_BUILD=0` prevent the bundled build script's download/automatic native-build fallback (Cargo `--offline` alone does not prohibit that fallback). ORT's existing library location is also explicit. Inherited `ORT_*`/`ZVEC_*` overrides are refused. Empty targets establish fresh emitted Cargo artifacts; they do not content-attest every Cargo registry source, operating-system linker/compiler, or external header/configuration input. The pinned Rust/Cargo tools and product Git inputs retain their separate checks.

`native-guards.py.in` fingerprints all `.so`-named entries in the declared zvec and ORT loader directories, including each symlink target, resolved regular file, byte count and SHA-256. It also fingerprints the presence/contents of zvec's additional relative RUNPATH directories; an absent directory becoming present fails. Before and after each build the inventory must match. The run wrapper requires this inventory in the new build attestation, replaces inherited `LD_LIBRARY_PATH` with exactly the declared primary directories, and removes all inherited `LD_*` variables and `GLIBC_TUNABLES` from child environments. Only removed variable names are recorded. Required primary directories must be real absolute directories; library symlinks may resolve only inside the declared primary directories.

Both run modes also require a separately prepared private [external-model manifest](model-guards-README.md). For setup the native inventory is checked before launch and after return. For trials it is checked before each root fixture copy completes and after each successful process, using a scoped wrapper around the immutable runner's provider parser. That parser runs after the original elapsed clock has stopped. Exactly nine copies and nine post-arm checks are required; the copy/provider hooks, environment and argv are restored even on failure. A failed operation also retains the native endpoint check or its failure class in its private mode-0600 record. These checks cost hashing time outside the original trial clock.

Read-only ELF inspection of the installed inputs on 2026-09-30 found zvec's RUNPATH `$ORIGIN/../lib64:$ORIGIN/../lib:$ORIGIN` and ORT's RUNPATH `$ORIGIN`. Those two additional zvec directories were absent and are included as declared search locations. The declared primary libraries also depend on system libraries (`libdl`, `librt`, `libpthread`, `libm`, `libc`, the ELF loader, and for ORT `libstdc++`/`libgcc_s`). This attestation covers the declared loader files and search directories only. It does **not** prove actual process mappings, pin those system/transitive libraries, exclude every later dynamic load, or make an endpoint fingerprint continuous monitoring. A change that is reverted between endpoints can escape detection. A trial requiring full native runtime identity must additionally retain its resolved system dependencies and actual mapping evidence; these wrappers make no such claim.

Fake-only checks (no Cargo, native loading, models, PostgreSQL, or measurement):

```sh
python3 benchmarks/harnesses/restart-floor-2026-09-30/test-native-build-guards.py.in
python3 benchmarks/harnesses/restart-floor-2026-09-30/test-fixture-guards.py.in
python3 benchmarks/harnesses/restart-floor-2026-09-30/test-model-guards.py.in
```

All reject optimized Python. Negative cases cover reused dependencies/proc macros/build scripts, artifacts outside the private target, changed library bytes/links, new loader files/search directories, uncontrolled native/compiler environment, a library changed during a fake arm, exact nine endpoints, and hook/environment restoration on failure.
